# Backend Overview

## Backend Architecture
The backend is built on FastAPI with Python 3.12, deployed via Docker and served with Uvicorn as a high-performance ASGI server. The architecture follows a modular layered design — routes, services, agent, models, and middleware — ensuring separation of concerns and scalability. Persistence is managed with SQLite in WAL (Write-Ahead Logging) mode, while data validation and environment configuration are powered by Pydantic v2 and pydantic-settings. User sessions are handled through signed JWT tokens stored in httpOnly cookies, with per-IP rate limiting and automatic daily expiration. A scheduler based on APScheduler runs scheduled cleanup tasks (soft delete) at 00:05 UTC.

## Intelligent Conversational Agent
The core of the system is a conversational agent built with LangGraph, orchestrating a state graph with specialized nodes: classifier, retriever, generator, rejector, and contact handler. The classifier, powered by GPT-4o-mini via OpenRouter, categorizes each message as IN_DOMAIN, OUT_OF_DOMAIN, PROMPT_INJECTION, or CONTACT, conditionally routing the flow to the corresponding branch. For valid queries, a RAG (Retrieval-Augmented Generation) pipeline performs in-memory vector search using cosine similarity over embeddings generated with text-embedding-3-small, feeding the main generator based on Claude 3.5 Sonnet. Responses are delivered to the frontend in real time via NDJSON streaming, serialized with orjson for maximum efficiency.

## Security, Observability & Integrations
The system implements multiple security layers: prompt injection detection at the classification level, granular rate limiting (10 messages and 2 emails per day per IP), and a database-stored prompt system with no external exposure. Traceability is achieved through LangSmith as the agent observability platform, complemented by structured logging with request ID tracking and latency metrics. The contact module integrates asynchronous email delivery with aiosmtplib and automatic retries via tenacity (up to 5 attempts with exponential backoff), persisting each lead in the database and sending i18n confirmation emails to the user.
